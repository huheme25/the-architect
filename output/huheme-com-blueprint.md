## 0. Contexto para el constructor (LEE ESTO PRIMERO)

Estás reconstruyendo **huheme.com**, el sitio personal de Beto Herrera (finanzas, estrategia y tecnología; educador de un seminario de rentabilidad en Guadalajara, México).

**Hoy** el sitio es 100% estático (HTML/CSS/JS a mano) desplegado por FTP a Hostinger. **Lo reconstruyes** como una app Astro 5 (SSR) que conserva el blog público y le agrega un **área privada para miembros** (alumnos del seminario) con contenido gateado y un directorio de networking.

**Dos reglas que dominan todo el proyecto:**
1. **NO se pierde nada de lo que ya existe.** Hay URLs vivas ya compartidas por correo (ver §5 Migración). Romperlas rompe descargas prometidas a suscriptores. La migración es *additiva*, no destructiva.
2. **Gratis y/o open-source, techo $10 USD/mes.** Todo el stack corre en free tier. Cero servicios de pago en la Fase 1.

## 1. Project Overview

### Vision
huheme.com pasa de ser un blog estático a una **plataforma de contenido con membresía**. El público general sigue leyendo *El Briefing* diario y los *deep dives* de las ponencias de Empresarios Jóvenes (CANACO GDL), con transcripciones descargables. Los **alumnos del seminario de rentabilidad** se registran con su perfil y su empresa, acceden a un área privada con las clases (audio + transcripción) y los deep dives, y se encuentran entre sí en un **directorio de networking**. El objetivo de negocio: generar tracción con valor gratuito y, en una **Fase 2**, monetizar los briefings y el seminario con suscripciones.

### Goals
- Migrar el sitio actual a Astro **sin perder una sola página, descarga ni URL**, conservando el diseño editorial.
- Permitir **registro de miembros restringido a alumnos** (allowlist de correos) con login sin contraseña (magic link).
- Servir **contenido solo-miembros** (audio + transcripciones + deep dives) de forma segura.
- Ofrecer un **directorio de networking** donde los miembros ven perfiles y empresas entre sí.
- Dejar la **monetización (Fase 2) enchufable** sin re-arquitectura.

### Success Metrics
- 100% de las URLs legacy (listadas en §5) responden igual tras el cutover.
- Un alumno en la allowlist completa registro → perfil → ve el directorio y descarga una clase, en < 2 min, sin contraseña.
- Costo de infraestructura mensual: **$0**.
- Lighthouse ≥ 95 en páginas públicas (Astro envía cero JS por defecto).

## 4. Data Model

> El contenido **público** (briefings, ponencias) vive en `src/content/` como Markdown — **no** en la base de datos. La base de datos solo guarda **miembros, empresas, allowlist y el registro de contenido gateado**.

**allowlist** — correos de alumnos pre-aprobados. Solo estos pueden registrarse.
| Field | Type | Notes |
|-------|------|-------|
| email | text | PK, lowercase |
| nombre | text | opcional, para personalizar bienvenida |
| nota | text | opcional (ej. "Generación 2026-1") |
| added_at | timestamptz | default now() |

**profiles** — un registro por miembro (1:1 con `auth.users`).
| Field | Type | Notes |

| nombre | text | requerido |
| telefono | text | opcional |
| puesto | text | cargo en su empresa |
| bio | text | breve |
| foto_url | text | opcional (Storage bucket público `avatars`) |

| visible | boolean | default true — aparecer en el directorio |

**companies** — empresa del miembro (1:1 con profile en MVP).
| Field | Type | Notes |
|-------|------|-------|

| owner_id | uuid | FK → profiles.id, único |

| tamano | text | enum sugerido: micro/pequeña/mediana/grande |

| Field | Type | Notes |
|-------|------|-------|

| slug | text | único |
| tipo | text | 'clase' \| 'deep-dive' |
| titulo | text | |
| descripcion | text | |
| fecha | date | |
| audio_path | text | ruta en bucket privado `miembros` (nullable) |

### Relationships
- `profiles.id` → `auth.users.id` (1:1).
- `companies.owner_id` → `profiles.id` (1:1 en MVP; preparado para 1:N a futuro).
- `content_items` es independiente (lo administra Beto vía SQL/seed o un panel simple).

### Database Schema (Postgres / Supabase)
```sql
-- ===== TABLAS =====
create table allowlist (
  email text primary key,
  nombre text,
  nota text,
  added_at timestamptz not null default now()
);

create table profiles (
  id uuid primary key references auth.users(id) on delete cascade,
  email text unique not null,
  nombre text not null,
  telefono text,
  puesto text,
  bio text,
  foto_url text,
  links jsonb default '{}'::jsonb,
  visible boolean not null default true,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create table companies (
  id uuid primary key default gen_random_uuid(),
  owner_id uuid unique not null references profiles(id) on delete cascade,
  nombre text not null,
  giro text,
  tamano text,
  ciudad text,
  sitio text,
  descripcion text
);

create table content_items (
  id uuid primary key default gen_random_uuid(),
  slug text unique not null,
  tipo text not null check (tipo in ('clase','deep-dive')),
  titulo text not null,
  descripcion text,
  fecha date,
  audio_path text,
  transcript_path text,
  html text,
  created_at timestamptz not null default now()
);

-- ===== RLS =====
alter table profiles      enable row level security;
alter table companies     enable row level security;
alter table content_items enable row level security;
alter table allowlist     enable row level security; -- sin policies = solo service_role

-- Directorio: cualquier miembro autenticado ve los perfiles visibles
create policy "miembros leen perfiles visibles" on profiles
  for select using (auth.role() = 'authenticated' and visible = true);
-- Cada quien edita SOLO su perfil
create policy "edita su propio perfil" on profiles
  for all using (auth.uid() = id) with check (auth.uid() = id);

create policy "miembros leen empresas" on companies
  for select using (auth.role() = 'authenticated');
create policy "edita su propia empresa" on companies
  for all using (auth.uid() = owner_id) with check (auth.uid() = owner_id);

-- Contenido gateado: legible por miembros autenticados (los archivos se sirven con signed URL)
create policy "miembros leen contenido" on content_items
  for select using (auth.role() = 'authenticated');

-- ===== ALLOWLIST GATE (defensa en profundidad) =====
-- Auth Hook "Before User Created": rechaza el alta si el email NO está en allowlist.
-- (Se registra en Supabase → Auth → Hooks. Validación PRIMARIA va también en /entrar.)
create function public.gate_signup()
returns trigger language plpgsql security definer as $$
begin
  if not exists (select 1 from allowlist where email = lower(new.email)) then
    raise exception 'email no autorizado';
  end if;
  return new;
end; $$;

-- ===== Crear profile automáticamente al confirmarse el usuario =====
create function public.handle_new_user()
returns trigger language plpgsql security definer as $$
begin
  insert into public.profiles (id, email, nombre)
  values (new.id, new.email, coalesce(new.raw_user_meta_data->>'nombre', split_part(new.email,'@',1)));
  return new;
end; $$;
create trigger on_auth_user_created
  after insert on auth.users for each row execute function public.handle_new_user();
```

## 6. API Design

### Routes Overview
| Method | Path | Description | Auth |
|--------|------|-------------|------|
| GET | `/auth/callback` | Intercambia el code del magic link por sesión (cookies) | público |
| POST | `/entrar` (action) | Valida email contra allowlist y envía magic link | público |
| GET | `/salir` | Cierra sesión y limpia cookies | sesión |
| GET | `/api/descargar/[id]` | Devuelve **signed URL** (60s) de un archivo gateado | miembro |
| POST | `/api/perfil` | Upsert de perfil + empresa del miembro | miembro |
| GET | `/api/health` | Query trivial a Postgres (keep-alive anti-pausa) | público (cron) |

### Key Endpoints Detail

**POST `/entrar`** (Astro Action o endpoint):
1. Normaliza `email` a minúsculas. Valida formato.
2. `admin.from('allowlist').select('email').eq('email', email)` con **service role** (server-only). Si no existe → responde genérico ("Si tu correo está autorizado, te llegó un enlace") sin revelar si está o no en la lista.
3. Si existe → `supabase.auth.signInWithOtp({ email, options:{ emailRedirectTo: SITE_URL + '/auth/callback' }})`.
4. El Auth Hook `gate_signup` es la segunda barrera por si alguien evade el endpoint.

**GET `/api/descargar/[id]`**:
1. `requireMember()` → si no hay sesión, 401/redirect a `/entrar`.
2. Busca `content_items` por id → toma `transcript_path`/`audio_path`.
3. `supabase.storage.from('miembros').createSignedUrl(path, 60)` (server-side).
4. Responde `302` al signed URL (o JSON con la URL). **Nunca** expone la ruta ni hace público el bucket.

**Response shape estándar** (JSON): `{ ok: boolean, data?: T, error?: string }`.

## 8. Authentication & Authorization

### Auth Flow
1. Alumno entra a `/entrar`, escribe su correo.
2. Server valida el correo contra **allowlist** (service role).
3. Supabase envía **magic link** (vía Resend/SMTP propio) → el alumno hace clic.
4. `/auth/callback` intercambia el code por sesión y setea cookies (`@supabase/ssr`).
5. Trigger `handle_new_user` crea su `profile`. Primera vez → redirige a `/miembros/perfil` para completar datos + empresa.
6. Visitas siguientes → `/miembros`.

### Protected Routes
- **Públicas:** `/`, `/briefing/*`, `/empresarios-jovenes/*`, `/entrar`, todos los archivos de `public/`.
- **Protegidas (`/miembros/*` y `/api/{descargar,perfil}`):** requieren sesión. `src/middleware.ts` corre `getUser()` y redirige a `/entrar` si no hay sesión.

### Roles & Permissions
| Role | Can Do |
|------|--------|
| Visitante | Leer blog, briefings, ponencias; descargar transcripciones públicas; suscribirse a Substack |
| Miembro (alumno) | Todo lo anterior + área privada, descargar clases/deep-dives, ver directorio, editar su perfil/empresa |
| Admin (Beto) | Gestiona allowlist y `content_items` vía SQL/seed (panel opcional a futuro) |

### Session Management
- Cookies httpOnly gestionadas por `@supabase/ssr` (`createServerClient` con `getAll`/`setAll`).
- **Proteger SIEMPRE con `getUser()`/`getClaims()`, NUNCA `getSession()`** (este no verifica firma server-side).
- **No cachear** respuestas con sesión en Cloudflare: header `Cache-Control: no-store` en rutas de `/miembros/*` y auth (un CDN puede filtrar el token de un usuario a otro).
- Crear el cliente Supabase **dentro del request handler**, no a nivel de módulo (evita fuga de sesión entre requests en runtime edge).

## 13. Testing Strategy

### Unit Tests (Vitest)
- `allowlist`: email autorizado pasa, no autorizado se rechaza (incluye normalización a minúsculas).
- `requireMember`: sin sesión → rechaza; con sesión → pasa.

### Integration Tests
- `/api/descargar/[id]`: sin sesión → 401; con sesión → 302 a signed URL válida.
- `/api/perfil`: upsert crea/actualiza profile + company del usuario correcto (RLS).

### E2E (Playwright, flujos críticos)
1. **Login alumno:** allowlist → magic link → callback → `/miembros`.
2. **No-alumno:** `/entrar` con correo fuera de la lista → no recibe acceso.
3. **Descarga gateada:** miembro descarga una clase; anónimo es bloqueado.
4. **Preservación:** las URLs de §5 responden `200` (smoke test post-deploy).

- Crea el cliente Supabase DENTRO del handler, nunca a nivel de módulo (runtime edge).

- Archivos gateados: bucket privado + createSignedUrl server-side. Nunca URL pública.
