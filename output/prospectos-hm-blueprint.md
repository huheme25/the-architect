## 1. Project Overview

### Visión

**prospectos-hm** es una webapp interna mobile-first para la captura rápida de prospectos comerciales en campo. Un vendedor visita tiendas potenciales en su ruta, abre la app en su celular, llena un formulario corto (datos de la tienda, productos de interés, GPS opcional, foto opcional, comentarios) y queda registrado en Postgres. Un administrador consulta los prospectos desde un dashboard de escritorio, los filtra, cambia su estatus de seguimiento y los descarga en CSV para llevarlos al CRM principal o analizarlos.

El objetivo es **tiempo de construcción mínimo** y **deploy a producción en minutos**, todo dentro de tiers gratuitos. Empieza con 1 vendedor (prueba) y escala a equipo de prospección sin reescribir.

### Goals

- Capturar un prospecto en menos de 60 segundos desde el celular del vendedor.
- GPS y foto opcionales pero a un tap de distancia (cámara nativa, geolocalización del navegador).
- Admin dashboard con tabla filtrable, detalle por lead, cambio de estatus, export CSV.
- Cero costos durante la prueba (Neon free + Vercel Hobby + Clerk free + Vercel Blob free).
- Escalable a 5-20 vendedores sin tocar arquitectura (Clerk maneja invitaciones, Postgres aguanta).

### Success Metrics

- **Captura sub-60s**: tiempo medido desde abrir la app hasta tap de submit en un prospecto típico.
- **0 fricciones de auth**: sesión persistente, vendedor abre la app y captura sin re-login frecuente.
- **Export útil**: CSV se importa al CRM/Excel sin re-formato manual.
- **Cobertura visual**: ≥70% de leads tienen foto y GPS (señal de adopción real).

## 4. Data Model

### Entidades

**Lead** — un prospecto comercial capturado en campo.

| Field | Type | Notes |
|-------|------|-------|
| `id` | `String` | `cuid()`, primary key |
| `createdAt` | `DateTime` | `default(now())`, indexado |
| `updatedAt` | `DateTime` | `@updatedAt` |
| `vendedorId` | `String` | Clerk userId del vendedor que capturó. Indexado. |
| `vendedorEmail` | `String` | Email del vendedor (snapshot, para mostrar en tabla sin llamar a Clerk) |
| `nombreTienda` | `String` | **Requerido**. Nombre del establecimiento. |
| `nombreContacto` | `String` | **Requerido**. Persona con quien se habló. |
| `telefono` | `String?` | Opcional |
| `email` | `String?` | Opcional |
| `direccion` | `String` (Text) | **Requerido**. Texto libre. |
| `latitud` | `Float?` | Opcional, viene de `navigator.geolocation` |
| `longitud` | `Float?` | Opcional |
| `fotoUrl` | `String?` | URL pública de Vercel Blob |
| `productosInteres` | `String` (Text) | **Requerido**. Texto libre multilínea. |
| `comentarios` | `String?` (Text) | Opcional, multilínea |
| `status` | `LeadStatus` | Enum, `default(NUEVO)`. Indexado. |

**LeadStatus** (enum):
- `NUEVO` — recién capturado, no se ha contactado
- `CONTACTADO` — admin/vendedor ya hizo seguimiento
- `CONVERTIDO` — ya es cliente
- `DESCARTADO` — no fue viable

### Relationships

Por ahora **no hay tabla `User` propia**: Clerk maneja usuarios. `Lead.vendedorId` es el `userId` de Clerk. Si más adelante se quieren rutas, equipos, comisiones, etc., se agrega `User` y se relaciona.

### Database Schema

```prisma
// prisma/schema.prisma
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model Lead {
  id               String     @id @default(cuid())
  createdAt        DateTime   @default(now())
  updatedAt        DateTime   @updatedAt

  vendedorId       String
  vendedorEmail    String

  nombreTienda     String
  nombreContacto   String
  telefono         String?
  email            String?
  direccion        String     @db.Text

  latitud          Float?
  longitud         Float?
  fotoUrl          String?

  productosInteres String     @db.Text
  comentarios      String?    @db.Text

  status           LeadStatus @default(NUEVO)

  @@index([createdAt])
  @@index([vendedorId])
  @@index([status])
  @@map("leads")
}

enum LeadStatus {
  NUEVO
  CONTACTADO
  CONVERTIDO
  DESCARTADO
}
```

## 5. API Design

### Routes Overview

| Method | Path | Description | Auth |
|--------|------|-------------|------|
| POST   | `/api/leads`         | Crear nuevo lead | vendedor o admin |
| GET    | `/api/leads`         | Listar leads (paginado, con filtros) | admin |
| GET    | `/api/leads/[id]`    | Detalle de un lead | admin |
| PATCH  | `/api/leads/[id]`    | Actualizar status / campos | admin |
| DELETE | `/api/leads/[id]`    | Eliminar lead (hard delete por simplicidad) | admin |
| GET    | `/api/leads/export`  | Descargar CSV con filtros aplicados | admin |
| POST   | `/api/upload`        | Subir foto a Vercel Blob, devuelve URL | vendedor o admin |

### Endpoint Detail

#### `POST /api/leads`

**Auth**: Clerk userId requerido. Cualquier usuario autenticado puede crear (vendedor y admin).

**Request body** (validado con Zod):
```ts
{
  nombreTienda: string (1..200),
  nombreContacto: string (1..200),
  telefono?: string (max 30),
  email?: string (email format, max 200),
  direccion: string (1..1000),
  latitud?: number (-90..90),
  longitud?: number (-180..180),
  fotoUrl?: string (url),
  productosInteres: string (1..2000),
  comentarios?: string (max 2000),
}
```

**Response 201**:
```json
{ "id": "clx...", "createdAt": "2026-05-05T...", "status": "NUEVO" }
```

**Errores**: 400 validation, 401 sin sesión, 500 db.

#### `GET /api/leads`

**Auth**: solo admin (chequeo de `publicMetadata.role === "admin"`).

**Query params**:
- `q`: búsqueda en `nombreTienda`, `nombreContacto`, `direccion` (ILIKE `%q%`)
- `status`: filtro por enum
- `from`, `to`: rango de fechas ISO
- `vendedorId`: filtro por vendedor
- `page` (default 1), `pageSize` (default 50, max 200)

**Response 200**:
```json
{
  "data": [Lead, ...],
  "page": 1,
  "pageSize": 50,
  "total": 234
}
```

#### `PATCH /api/leads/[id]`

**Auth**: admin.

**Request body** (parcial):
```ts
{
  status?: "NUEVO" | "CONTACTADO" | "CONVERTIDO" | "DESCARTADO",
  // resto de campos editables si se quiere edición completa
}
```

**Response 200**: lead actualizado.

#### `GET /api/leads/export`

**Auth**: admin.

**Query params**: mismos filtros que `GET /api/leads` (sin paginación — exporta todo lo filtrado).

**Response**:
- `Content-Type: text/csv; charset=utf-8`
- `Content-Disposition: attachment; filename="prospectos-YYYY-MM-DD.csv"`
- Body: CSV streameado fila por fila (no carga todo en memoria).

**Columnas del CSV** (en este orden):
```
createdAt, status, vendedorEmail, nombreTienda, nombreContacto,
telefono, email, direccion, latitud, longitud, fotoUrl,
productosInteres, comentarios
```

UTF-8 con BOM para que Excel lo abra bien con acentos.

#### `POST /api/upload`

**Auth**: cualquier usuario autenticado.

**Request**: `multipart/form-data` con campo `file` (image/jpeg, image/png, image/webp). Max 5 MB.

**Response 200**:
```json
{ "url": "https://...vercel-storage.com/leads/abc.jpg" }
```

**Implementación**:
```ts
import { put } from '@vercel/blob';
const blob = await put(`leads/${cuid()}.${ext}`, file, { access: 'public' });
return Response.json({ url: blob.url });
```

### State Management

- **Server Components por defecto** para fetching inicial (lista de leads, detalle).
- **Client Components** solo donde hay interactividad: forms, filtros, tabla, dropdowns.
- **No global store** (no Zustand, no Redux). React Hook Form maneja form state, `useState` local para UI.
- **Cache**: `revalidatePath('/admin')` después de mutaciones, sin `useSWR` ni `react-query` (pequeña escala).
- **Optimistic updates** en cambio de status (cambia el badge instantáneo, revierte si falla).

## 8. Authentication & Authorization

### Auth Flow

1. Usuario abre la app → `middleware.ts` checa Clerk session → si no, redirige a `/sign-in`.
2. Login con email/password en Clerk's hosted UI (componentes `<SignIn />` y `<SignUp />`).
3. Después de login → `/` lee `publicMetadata.role`:
   - `admin` → redirect a `/admin`
   - cualquier otro o `undefined` → redirect a `/captura` (asume vendedor)
4. Sesión persistente vía cookies HttpOnly de Clerk.

### Protected Routes

Configurado en `middleware.ts`:

```ts
import { clerkMiddleware, createRouteMatcher } from '@clerk/nextjs/server';

const isPublic = createRouteMatcher(['/sign-in(.*)', '/sign-up(.*)']);
const isAdminRoute = createRouteMatcher(['/admin(.*)', '/api/leads(.*)']);

export default clerkMiddleware(async (auth, req) => {
  if (isPublic(req)) return;

  const { userId, sessionClaims } = await auth();
  if (!userId) return auth.redirectToSignIn();

  if (isAdminRoute(req)) {
    const role = (sessionClaims?.publicMetadata as any)?.role;
    if (role !== 'admin') {
      // si no es admin pero accede a /admin, mándalo a captura
      return Response.redirect(new URL('/captura', req.url));
    }
  }
});

export const config = {
  matcher: ['/((?!_next|.*\\..*).*)'],
};
```

`/api/leads` (POST de captura) lo usa el vendedor — está dentro de `/api/leads` que arriba marca como admin. **Excepción explícita en el handler**: `POST /api/leads` permite cualquier autenticado, `GET / PATCH / DELETE` solo admin. El middleware deja pasar y el handler hace el chequeo fino.

### Roles & Permissions

| Role | Can Do |
|------|--------|
| `admin` | Todo: ver dashboard, ver/editar/eliminar leads, exportar CSV, capturar leads. |
| `vendedor` (default) | Solo capturar leads en `/captura`. No accede a `/admin`. |

**Asignación de rol**: manualmente desde el [Clerk Dashboard](https://dashboard.clerk.com) → Users → user → Public metadata → `{ "role": "admin" }`. No hace falta UI de gestión de usuarios para la prueba.

### Session Management

Clerk maneja sesiones con cookies HttpOnly + refresh automático. No necesitas implementar JWT manualmente. `auth()` en server components / route handlers, `useUser()` / `useAuth()` en client components.

### Step 6: API — POST /api/leads (captura básica sin foto/GPS aún)

Crea `src/app/api/leads/route.ts`:
```ts
import { NextRequest, NextResponse } from 'next/server';
import { auth, currentUser } from '@clerk/nextjs/server';
import { db } from '@/lib/db';
import { LeadCreateSchema, LeadsFilterSchema } from '@/lib/validators';
import { requireAdmin } from '@/lib/auth';

export async function POST(req: NextRequest) {
  const { userId } = await auth();
  if (!userId) return NextResponse.json({ error: 'Unauthorized' }, { status: 401 });

  const user = await currentUser();
  const json = await req.json();
  const parsed = LeadCreateSchema.safeParse(json);
  if (!parsed.success) {
    return NextResponse.json({ error: 'ValidationError', issues: parsed.error.issues }, { status: 400 });
  }

  const lead = await db.lead.create({
    data: {
      ...parsed.data,
      telefono: parsed.data.telefono || null,
      email: parsed.data.email || null,
      fotoUrl: parsed.data.fotoUrl || null,
      comentarios: parsed.data.comentarios || null,
      vendedorId: userId,
      vendedorEmail: user?.emailAddresses[0]?.emailAddress ?? '',
    },
  });
  return NextResponse.json(lead, { status: 201 });
}

export async function GET(req: NextRequest) {
  await requireAdmin();
  const params = Object.fromEntries(new URL(req.url).searchParams);
  const f = LeadsFilterSchema.parse(params);

  const where: any = {};
  if (f.q) {
    where.OR = [
      { nombreTienda: { contains: f.q, mode: 'insensitive' } },
      { nombreContacto: { contains: f.q, mode: 'insensitive' } },
      { direccion: { contains: f.q, mode: 'insensitive' } },
    ];
  }
  if (f.status) where.status = f.status;
  if (f.vendedorId) where.vendedorId = f.vendedorId;
  if (f.from || f.to) {
    where.createdAt = {};
    if (f.from) where.createdAt.gte = new Date(f.from);
    if (f.to) where.createdAt.lte = new Date(f.to);
  }

  const [data, total] = await Promise.all([
    db.lead.findMany({
      where,
      orderBy: { createdAt: 'desc' },
      skip: (f.page - 1) * f.pageSize,
      take: f.pageSize,
    }),
    db.lead.count({ where }),
  ]);
  return NextResponse.json({ data, total, page: f.page, pageSize: f.pageSize });
}
```

import { MapPin, Loader2 } from 'lucide-react';

export function GpsButton({
  onCapture,
  hasCoords,
}: {
  onCapture: (lat: number, lng: number) => void;

        setLoading(false);
        toast.error('No se pudo obtener ubicación: ' + err.message);
      },
      { enableHighAccuracy: true, timeout: 10000 }
    );
  };
  return (
    <Button type="button" variant={hasCoords ? 'secondary' : 'outline'} onClick={handle} disabled={loading} className="w-full">
      {loading ? <Loader2 className="mr-2 h-4 w-4 animate-spin" /> : <MapPin className="mr-2 h-4 w-4" />}
      {hasCoords ? 'Ubicación capturada ✓ (volver a capturar)' : 'Capturar ubicación GPS'}
    </Button>
  );
}

import { auth } from '@clerk/nextjs/server';
import { put } from '@vercel/blob';
import { NextRequest, NextResponse } from 'next/server';

const MAX_BYTES = 5 * 1024 * 1024;
const ALLOWED = ['image/jpeg', 'image/png', 'image/webp'];

export async function POST(req: NextRequest) {
  const { userId } = await auth();
  if (!userId) return NextResponse.json({ error: 'Unauthorized' }, { status: 401 });

  const formData = await req.formData();
  const file = formData.get('file') as File | null;
  if (!file) return NextResponse.json({ error: 'NoFile' }, { status: 400 });
  if (file.size > MAX_BYTES) return NextResponse.json({ error: 'TooLarge' }, { status: 400 });
  if (!ALLOWED.includes(file.type)) return NextResponse.json({ error: 'BadType' }, { status: 400 });

  const ext = file.type === 'image/png' ? 'png' : file.type === 'image/webp' ? 'webp' : 'jpg';
  const key = `leads/${crypto.randomUUID()}.${ext}`;
  const blob = await put(key, file, { access: 'public', addRandomSuffix: false });
  return NextResponse.json({ url: blob.url });
}

import Image from 'next/image';
import { useRef, useState } from 'react';
import { toast } from 'sonner';

export function PhotoInput({
  value,
  onChange,

  value: string | undefined;

  const inputRef = useRef<HTMLInputElement>(null);

        ref={inputRef}
        type="file"
        accept="image/*"
        capture="environment"
        className="hidden"
        onChange={handleFile}

  'createdAt','status','vendedorEmail','nombreTienda','nombreContacto',

const escape = (v: unknown): string => {
  if (v === null || v === undefined) return '';

      l.longitud ?? '',
      l.fotoUrl ?? '',
      l.productosInteres,
      l.comentarios ?? '',
    ].map(escape).join(',')
  );
  return '﻿' + HEADERS.join(',') + '\n' + rows.join('\n');

## 13. Testing Strategy

> Para una **prueba con 1 vendedor**, no se justifica suite extensa. El criterio: tests donde el costo de fallar en prod es alto.

### Unit Tests (opcional en la v1)

Si quieres cubrir lo crítico:
- `src/lib/csv.ts` — escape de comillas, manejo de nulls, formato UTF-8 BOM.
- `src/lib/validators.ts` — schemas con casos edge (string vacío, email malformado, lat/lng fuera de rango).

Stack: **Vitest** (`pnpm add -D vitest @testing-library/react`).

### Integration Tests (opcional)

Tests de las API routes con un Postgres efímero (Neon branch ephemeral o Docker postgres). Skipear en la v1.

### E2E Tests

**Recomendado para v1.1**, no para la prueba inicial. Cuando crezca:
- **Playwright** con un test crítico: login → /captura → llenar form → submit → ver en /admin → exportar CSV → assertion sobre el contenido.

### Smoke Test Manual (obligatorio antes de cada deploy)

Antes de mergear a `main`:
1. Login como vendedor → captura un lead con foto y GPS.
2. Login como admin → ve el lead en la tabla.
3. Cambia status, guarda, recarga, persiste.
4. Filtra por status, sale solo el correcto.
5. Exporta CSV, abre en Excel, lee bien con acentos.

## Architecture

### Directory Structure

- `src/app/` — App Router. Páginas server por default, `_components/` colocados con cada ruta para componentes específicos.
- `src/app/api/` — Route handlers (REST). Auth chequeada dentro de cada handler.

- `src/components/layout/` — Sidebar, Header.
- `src/lib/` — `db.ts` (Prisma singleton), `auth.ts` (helpers Clerk), `validators.ts` (Zod schemas), `csv.ts`, `utils.ts`.
- `prisma/schema.prisma` — Fuente de verdad del modelo de datos.
- `src/middleware.ts` — Clerk middleware: protege todo excepto `/sign-in`, `/sign-up`. `/admin/*` requiere `publicMetadata.role === "admin"`.

### Data Flow

- **Captura (vendedor)**: form client component → `fetch('/api/leads', POST)` → handler valida con Zod → Prisma create → response → toast.
- **Admin lista**: server component hace `db.lead.findMany` directamente (no via API) → pasa a client component `LeadsTable` para sort/filter visual.
- **Admin mutaciones**: client → `PATCH /api/leads/[id]` → `revalidatePath('/admin')` → UI refleja.
- **Foto**: client mete file en FormData → `POST /api/upload` → server llama `put()` de @vercel/blob → devuelve URL pública → form la guarda en `fotoUrl`.
- **GPS**: 100% client-side con `navigator.geolocation.getCurrentPosition`.

### Key Patterns

- **Server Components por default.** Solo agregar `"use client"` cuando hay event handlers, hooks o estado.
- **Auth en server, dos veces:** middleware (gross-grain redirect) + handler/page (fine-grain `requireAdmin()`). Nunca confiar solo en el middleware.
- **Validación con Zod siempre en el server** aunque ya se validó en el client. El cliente miente.
- **Prisma client singleton** en `lib/db.ts` para no agotar conexiones en dev (HMR crea instancias nuevas si no se cachea en `globalThis`).
- **Path alias `@/`** apunta a `src/`. No usar imports relativos largos.
- **Mobile-first.** Cualquier UI nueva se diseña primero en 375px y luego se adapta a desktop.
- **Errores estructurados** desde API: `{ error: "TipoDeError", issues?: [...] }` con HTTP status correcto.

## 16. Reglas No Negociables (para el builder)

1. **Sigue el Build Order paso a paso.** Cada step se valida antes del siguiente. Si algo falla, no avanzar — diagnóstico primero.
2. **TypeScript strict, cero `any`** salvo en bordes con APIs externas, y comentando el motivo.
3. **Validación Zod en el server siempre.** Replicar el schema en el cliente para UX, pero el server es el guardián.

5. **Mobile-first en `/captura`.** Probar en celular real (`pnpm dev -H 0.0.0.0` + IP local) antes de declarar el form terminado.
